Nothing in the root package `lean-no-comments` imports this package, keeping the shipped `no-comments` executable free of `lean-intent` dependency weight. See [confirmation.md](confirmation.md) for the owner's confirmation record.

## Blind Second-Model Comparison (`BlindSecondModel.lean` and `Comparison.lean`)

`BlindSecondModel.lean` formalizes an independent reading of the owner-level specification, and `Comparison.lean` compares all 17 deliverables against their same-type `BlindSecondModel` records inside Lean with bi-directional `LeanIntent.BlindComparison.records` proofs (`0` `.cases` fallbacks and `0` unproved directions):

- **Bi-directional equivalence (`Comparison.lean`, 8 deliverables):** **Proved** both directions (`*_meets_blind` / `*_blind_meets`, derived from `*_meets_iff`) for `isFingerprintRecord`, `fingerprintRecord`, `firstOutOfOrderRecord`, `sortFingerprintsRecord`, `missingFromRecord`, `sourceOrderRecord`, `checkExactSyncRecord`, and `checkMonotonicFileRecord`, plus conditional equivalence when 1-based line numbers hold (`distinctLines_equiv_of_pos`, `analyzeComments_equiv_of_pos`) and when `analyses` has distinct `.file` keys (`validateCheck_equiv_of_nodup`).
- **Bi-directional separation on documented divergences (`Comparison.lean`, 9 deliverables):** **Proved** both separating witnesses (`*_separates_blind` / `*_blind_separates`) for the remaining 9 deliverables grounded in the documented specification divergences:
  - `diff_distinctLines_zero_line` (`distinctCommentLines`, `analyzeComments`): Synthetic `startLine = 0` is clamped via `max 1 c.startLine` by `BlindSecondModel.coveredLines` (`1` line) while `CoreSpec.DistinctLines` counts `[0, 1]` (`2` lines); real `FileMap` positions are 1-based.
  - `diff_validateCheck_duplicate_file` (`validateCheck`): Duplicate `FileAnalysis` entries for the same file fail under `RatchetSpec.ValidateOk` (`Array.find?` inspects the first match) while `BlindSecondModel.ValidCheck` checks `∃ a ∈ analyses` and passes when a later duplicate has zero comments; real `Runner` collects one analysis per unique tracked file.
  - `diff_collectRanges_plainDocComment` and `truncDashRange` (`collectRanges`): `CoreSpec.docKind` includes `Lean.Parser.Command.plainDocComment` in addition to `docComment` and `moduleDoc` (omitted by `BlindSecondModel.docKind`), and `CoreSpec` scans line comments up to the command range boundary `nextPos` whereas `BlindSecondModel.CommentSpelling` requires `after = "" ∨ after.startsWith "\n"` in the full input string (`truncDashRange` separates both directions).
  - `diff_classifyFile_segmentPrefix` (`classifyFile`, `classifyTracked`): `ConfigSpec.PrefixMatches` matches on `/` path-segment boundaries (`"Foo"` does not match `"FooBar.lean"`), whereas `BlindSecondModel.Classification` used `String.startsWith`.
  - `diff_parseConfig_cleanCtrl` (`parseConfig`, `parseRatchet`): `ConfigSpec.cleanStr` forbids `\n`, `\r`, `\t`, `\x00`, and `\\`, whereas `BlindSecondModel.CleanText` forbids all ASCII control chars `< 32` and `127` (`\x01` accepted vs. refused in both config `ratchet` and ratchet `file` paths).
  - `diff_checkToken_identMismatch` (`checkToken`): `CoreSpec.literalToken` round-trips identifier spelling through `Lean.Parser.tokenFn` (refusing a forged `.ident` whose raw slice is `"--"`), whereas `BlindSecondModel.LiteralAt` accepted any `.ident` constructor unconditionally.
